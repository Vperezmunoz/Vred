# API differences between indexed VRED releases

Generated by comparing `data/19.1/members.tsv` and `data/19.2/members.tsv` (19.1 = VRED 2027.1,
19.2 = VRED 2027.2). Class count: 690 -> 693. Member count: 8779 -> 8827. Only API
*signatures* are compared here; behaviour that changed without a signature change is not
visible in the index and is noted separately below only where it was observed.

## Added in 19.2 (VRED 2027.2)

| Area | What is new |
|---|---|
| Platform info (new service `vrPlatformService`, 28 members) | `getAppName`, `getAppVersionName`, `getVersionString`, `getPlatform`; folders `getBaseDir`, `getBinDir`, `getDataDir`, `getExeDir`, `getLibDir`, `getPluginsDir`, `getPreferencesDir`; DPI and icon/preview size getters (`getDpiX/Y`, `getDpiScaleX/Y`, `getMini/Small/Medium/LargeIconSizeX/Y`, `get...PreviewSizeX/Y`, `getTreeViewIconSize`) |
| Script plugin management (new `vrPluginService`, new class `vrdScriptPluginInfo`) | `getScriptPluginNames()`, `getScriptPluginInfos()`, `getScriptPluginInfo(name)`, `reloadScriptPlugins()`; `vrdScriptPluginInfo` get/set `PluginName`, `Author`, `ScriptFile` |
| File import | `vrFileIOService.importFiles(..., convertSceneUp=True)` has one more optional argument. Calls with only `files, parent` work in both releases |
| Images | `vrImageService.loadImage(image, path="image.png", ...)` - overload taking a `QImage`. The file-name overload exists in both. (In STLSmooth testing, building a texture from an in-memory image left the material's texture slot empty; loading the image from a file worked and is the portable choice) |
| GUI | `vrGUIService.getIcon(name)`, `getIconNames()` |
| Constraints | `vrConstraintService.groupNodes(nodes)` |
| Materials | `vrMaterialService.getMaterialIdPassColors()`; `vrdMDLMaterial.loadModuleFromString(data, moduleName="data.mdl")` |
| Render | `vrOSGWidget.get/setDepthShouldIncludeTransparentObjects`; `vrdRenderPasses.clearPasses()`, `get/setExportRenderpassesInVulkan` |

## Removed or changed

- `vrFileIOService.importFiles` signature changed as above (extra optional argument only).
- `vrdObjectSignal.getSignal(object)` is listed in 19.1 but not in 19.2.

## How to redo this comparison for a new release

```
py vredapi.py versions                      # which releases are indexed
```
then compare the two `members.tsv` files (first two columns are owner and signature), e.g. load
both into sets and print the differences. Update this file when a release is added.

## Release names

Internal folder number -> product: 18.2 = 2026.2, 19.0 = 2027, 19.1 = 2027.1, 19.2 = 2027.2.
Indexed today: 19.1 and 19.2 only (a VRED install must ship `doc\_sources` to be indexable).
