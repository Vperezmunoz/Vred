----------------
vrPhysicsService
----------------

.. py:class:: vrPhysicsService

(Inherits vrBaseService)

The     vrPhysicsService class.

This class provides access to the physics simulation in VRED. It allows adding, removing, and manipulating physics objects in the simulation.

This is an experimental feature and is subject to change in future releases. For now, it is only available for collision detection and not for actual physics simulations.

There are three types of physics objects that can be added to the simulation: Kinematic, Dynamic, and Static. A kinematic object is a physics object that is not affected by forces but can be controlled manually by the user. Only convex shapes are supported for kinematic objects, which means no triangle meshes can be used. A dynamic object is a physics object that is affected by forces and can interact with other objects in the simulation. It cannot be manually moved. Dynamic objects are currently not used in VRED. A static object is a physics object that is not affected by forces and can't be moved manually or by other objects or the user. The only valid configuration for a static object is the triangle mesh configuration.

Some notes on using this service:

At this moment, only convex shapes are really supported. So the best case is to use convex hulls. Triangle meshes are only partly supported. They can be used for static objects but not for moving objects. That means they must not be moved in any way in VRED after they have been added to the physics simulation or their collision shape will be out of sync with the actual object. PhysX is also very strict about the tessellation of the triangle meshes. If the tessellation is not good enough, they can cause problems or even errors.

For complex objects, convex decomposition can be used, which breaks down the object into multiple smaller convex shapes. The library used for that is v-hacd (https://github.com/kmammou/v-hacd). Almost all parameters of the library can be set in the vrdPhysicsConfig object to fine-tune the decomposition process.

The collision shapes of the objects are currently not visualized in VRED. They can be visualized in the NVidia PhysX Visual Debugger which can be connected to the physics simulation using the connectDebugger(host, port) function. The debugger must be started on the same machine as VRED before the connection can be established. The debugger can be downloaded from the NVidia website (https://developer.nvidia.com/nvidia-physx-visual-debugger).

Please also note that there is currently no detection if a child node of a registered node is moved or removed. If there are structural changes in the scene graph for a registered node, the node should be removed and then re-added to the physics simulation. It is not possible to add a node to the physics simulation for which a parent node is already registered. This is detected and results in an error when trying to add the node.

    Adds a dynamic object to the physics simulation.

    A dynamic object is a physics object that is affected by forces and can interact with other objects in the simulation. It cannot be moved manually. Valid configurations are vrdPhysicsHullConfig and vrdPhysicsConvexConfig.

    :param node: The node to add.
    :type node: vrdNode

    :param config: The configuration for the object.
    :type config: vrdPhysicsConfig

    :return: True if the object was added successfully, False otherwise.

    :type node: vrdNode

.. py:method:: vrPhysicsService.createGroup(name, parent=vrdPhysicsGroupNode())

    Creates a new physics group in the physics editor hierarchy.

    This function creates a new physics group node with the specified name. Physics groups are used to organize physics objects in a hierarchical structure within the physics editor. The group name will be automatically made unique if a group with the same name already exists. The created group is automatically added as a child of the specified parent group.

    :param name: The name for the new physics group.
    :type name: string

    :param parent: The parent physics group to add the new group to. If not specified or invalid, the root node will be used as parent.
    :type parent: vrdPhysicsGroupNode

    :return: The created physics group node, or an invalid node if creation failed.
    :rtype: vrdPhysicsGroupNode

.. py:method:: vrPhysicsService.createPhysicsObject(sceneNode, colliderType, colliderShape, parent=vrdPhysicsGroupNode())

    Creates a physics object from a scene node with specified collider type and shape.

    This function creates a physics object node in the physics editor hierarchy from an existing scene node. The physics object will use the specified collider type (Kinematic, Dynamic, or Static) and collider shape (Box, Sphere, Capsule, Plane, ConvexHull, etc.). The created physics object is automatically added as a child of the specified parent group.

    :param sceneNode: The scene node to create a physics object from.
    :type sceneNode: vrdNode

    :param colliderType: The collider type (Kinematic, Dynamic, or Static).
    :type colliderType: vrPhysicsTypes.ColliderType

    :param colliderShape: The collider shape to use for collision detection.
    :type colliderShape: vrPhysicsTypes.ColliderShape

    :param parent: The parent physics group to add the object to. If not specified or invalid, the root node will be used as parent.
    :type parent: vrdPhysicsGroupNode

    :return: The created physics object node, or an invalid node if creation failed.
    :rtype: vrdPhysicsObjectNode

.. py:method:: vrPhysicsService.setContactPointVisualizationPoolSize(size)

    Sets the size of the contact point visualization pool.

    This function configures the maximum number of contact points that can be visualized simultaneously. The pool is pre-allocated for performance reasons. A larger pool size allows more contact points to be displayed but uses more memory.

    Note: Changing the pool size will reinitialize the contact point visualization system. This should be done before enabling contact point visualization or when no contacts are currently being visualized.

    :param size: The pool size (number of contact point spheres to pre-allocate). Valid range: 64-4096. Default: 256.
    :type size: integer

.. py:method:: vrPhysicsService.setContactPointVisualizationScaling(scale)

    Sets the scaling factor for contact point visualization spheres.

    This function sets the size of the spheres used to visualize contact points. Larger values make contact points more visible, smaller values provide more precision. The base sphere radius is 0.5 units, which is multiplied by this scaling factor.

    :param scale: The scaling factor for contact point spheres.
    :type scale: float

.. py:method:: vrPhysicsService.setPhysicsUpdateFrequency(hz)

    Sets the physics update frequency.

    IMPORTANT: This does NOT change the physics simulation rate, which is always exactly 60Hz. This controls how often we check if enough time has accumulated to run a physics step.

    DEFAULT: 60Hz (optimal balance of accuracy and performance)

    Timer frequency vs Physics behavior:

    240Hz: Very smooth timing, high CPU overhead, research/validation use120Hz: Smooth timing, moderate overhead, high-precision simulation60Hz+: Optimal range, minimal timer overhead (DEFAULT)30-59Hz: May cause occasional missed steps, acceptable for simple collision<30Hz: Will cause multiple physics steps per timer call, basic scenarios only

    Performance presets (recommended):

    vrPhysicsService.setPhysicsHighPrecision() - 120Hz for robotics, scientific applicationsvrPhysicsService.setPhysicsStandard() - 60Hz for most applications (DEFAULT)vrPhysicsService.setPhysicsPowerSaving() - 30Hz for simple collision, battery optimization

    :param hz: Update frequency in Hertz. Valid range: 10-240Hz. Invalid values default to 60Hz.
    :type hz: integer
